The product backlog lists every functional requirement in the SRS (FR1.1--FR8.5), with its priority, linked user stories (US IDs from the Use Cases and User Stories document), the sprint it is planned for, and its story points. It is a living document: update it through a \texttt{docs/*} pull request whenever priorities, estimates or scope change.

\textbf{Scope decisions (sprint planning meeting):} Sprint 1 delivers F1--F4. Sprint 2 delivers F5, F6, F8 and one replacement feature for F7; practice quizzes (F7) are dropped from scope. The F7 replacement will be added here once the Product Owner confirms it.

\textbf{Story points:} Sprint 1 points are the Technical Lead's \emph{proposed} estimates (Fibonacci scale, 1 point $\approx$ half a day), to be confirmed by the team. Sprint 2 items are estimated at Sprint 2 planning. \textbf{Pri.} is the SRS priority.

\section*{Non-functional requirements (apply to every sprint)}
HTTPS (NFR5); server-side authorisation on every API route, reinforced by row-level security (NFR7); IBA domain check on the server (NFR8); contact details never in the directory (NFR10); search under 2 s at the 95th percentile on 1,000 members (NFR1, NFR2); usable at 360 px width (NFR13); every screen within three clicks of the dashboard (NFR14); lint and type-check in CI, no direct commits to \texttt{main} (NFR15); WCAG 2.1 AA basics (NFR17); rate-limited sign-in, registration and password reset (NFR20); a test for every High-priority FR (NFR21).
